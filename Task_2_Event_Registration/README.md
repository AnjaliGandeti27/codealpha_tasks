# Event Registration System

A backend-based Event Registration System developed using Node.js, Express.js, MongoDB, and Mongoose as part of my CodeAlpha Backend Development Internship.

## Project Purpose

The Event Registration System is a backend application that allows events to be created and participants to register for available events.

The system provides REST APIs to:

- Create events
- View all events
- Register participants for events
- View all registrations
- Check whether an event exists before registration
- Prevent duplicate registration for the same participant and event
- Handle invalid event IDs
- Handle invalid registration data
- Store event and registration information in MongoDB

## Data Design

### Event

The Event model stores information about an event.

Each event contains:

- `name` - Name of the event
- `description` - Description of the event
- `date` - Date of the event
- `location` - Location of the event
- `capacity` - Capacity specified for the event

Each event is automatically given a unique MongoDB `_id`.

The same event name can be used for different event sessions because each event document has its own unique `_id`.

### Registration

The Registration model stores information about participants who register for events.

Each registration contains:

- `participantName` - Name of the participant
- `participantEmail` - Email address of the participant
- `eventId` - ID of the event for which the participant registered
- `registrationDate` - Date and time when the registration was created

The `eventId` is used to identify the event associated with a registration.

## How the System Works

The application uses Node.js and Express.js to create the backend server and REST APIs.

Mongoose is used to communicate between the Node.js application and MongoDB.

The basic flow is:

```text
Postman / Client
       ↓
Express.js API
       ↓
Request Processing
       ↓
Mongoose
       ↓
MongoDB
       ↓
Response
```

### Event Creation Flow

1. The client sends event information using a POST request.
2. Express receives the request.
3. The event data is passed to the Event model.
4. Mongoose saves the event in MongoDB.
5. The server returns the created event in the response.

### Participant Registration Flow

1. The participant sends their name, email, and event ID.
2. The server checks whether the event exists.
3. The server checks whether the same participant is already registered for that event.
4. If the participant is already registered, the server returns a duplicate registration message.
5. If the event exists and the participant is not already registered, a registration is created.
6. The registration is stored in MongoDB.
7. The server returns a successful registration response.

### 2. Create an Event

**Method:** `POST`

**Endpoint:**

```text
/events
```

**Full URL:**

```text
http://localhost:3000/events
```

**Purpose:**

Creates a new event and stores it in MongoDB.

**Request Body:**

```json
{
  "name": "AI Workshop",
  "description": "Introduction to Artificial Intelligence",
  "date": "2026-08-20",
  "location": "Seminar Hall",
  "capacity": 100
}
```

**Example Successful Response:**

```json
{
  "message": "Event created successfully",
  "event": {
    "name": "AI Workshop",
    "description": "Introduction to Artificial Intelligence",
    "date": "2026-08-20T00:00:00.000Z",
    "location": "Seminar Hall",
    "capacity": 100,
    "_id": "EVENT_ID",
    "__v": 0
  }
}
```

The `_id` shown in the response is generated by MongoDB and is unique for each event.

### 4. Register a Participant

**Method:** `POST`

**Endpoint:**

```text
/registrations
```

**Full URL:**

```text
http://localhost:3000/registrations
```

**Purpose:**

Registers a participant for an existing event.

**Request Body:**

```json
  "participantEmail": "anjali@gmail.com",
```

It also checks whether the same participant email is already registered for the same event.

## Validation and Error Handling

The backend handles several important error cases.

### Event Not Found

If a participant tries to register using an event ID that does not exist, the server returns:

```json
{
  "message": "Event not found"
}
```

### Invalid Event ID

If the event ID format is invalid, the server handles the MongoDB/Mongoose `CastError` and returns:

```json
{
  "message": "Invalid event ID"
}
```

### Duplicate Registration

The system checks both:

- `participantEmail`
- `eventId`

This means the same participant cannot register twice for the same event.

For example, if a participant with:

```text
participantEmail: anjali@gmail.com
```

is already registered for a particular event, attempting to register the same email for the same event again will return:

```json
{
  "message": "Participant is already registered for this event"
}
```

The same participant can register for a different event because the `eventId` is different.

### Invalid Registration Data

Mongoose validation errors are handled by the backend and returned as an appropriate error response.

### Database or Server Errors

Unexpected database or server errors are handled using error responses so that the client receives information about the failure.

## Running the Project Locally

### Prerequisites

The following software should be installed:

- Node.js
- npm
- MongoDB
- MongoDB Compass
- Postman

### Step 1: Open the Project

Open the `Task_2_Event_Registration` folder in Visual Studio Code.

### Step 2: Install Dependencies

Open the terminal inside the project folder and run:

```bash
npm install
```

This installs the packages listed in `package.json`.

MongoDB should be running locally because the project uses:

```text
mongodb://localhost:27017/eventregistration
```

```bash
node server.js
```

```text

```

Open Postman and test the API endpoints described above.

For example:

